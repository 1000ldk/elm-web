# AboutページのUI調整（Elm）

## やったこと

同様の調子で機能を追加していきます。
次に私個人の情報開示のためのブログの `Page.About` を実装・調整しました。


## 実装内容

### 1. リンクリストの構造化

表示名とURLをレコード（`LinkItem`）として分離し、`List.map` で `<li><a>` に展開する形にしました。

```elm
type alias LinkItem =
    { label : String
    , url : String
    }


links : List LinkItem
links =
    [ { label = "GitHub", url = "https://github.com/1000ldk" }
    , { label = "X", url = "https://twitter.com/0zldk" }
    , { label = "Blog", url = "/" }
    ]


viewLink : LinkItem -> Html Msg
viewLink item =
    li [] [ a [ href item.url ] [ text item.label ] ]
```

`Home` モジュールの記事一覧（`li [] [a [href "/post/1"] [text "最初の記事"]]`）と同様のパターンであるため迷わず馴染んだ。

### 2. レイアウトの微調整

実装後、以下の見た目の問題が出た。

- 箇条書きの `・`（bullet）が画面左端に飛び出してしまう
- `Links` の見出しが `div` テキストのままで小さすぎる

原因は、テキストは `text-align: center` で中央揃えなのに `ul` はブロックとして画面幅いっぱいに広がっており、その中の bullet はデフォルトで左端に来ることだった。

対応：

- `Links` と `ul` を1つの `div` でくくり、`max-width` + `margin: auto` で細いカラムとして中央付近に配置
- `ul` に `list-style-position: inside` を指定し、bulletを文字の左端に揃える
- `Links` を `div` から `h2` に変更して見出しらしいサイズに

```elm
div
    [ style "max-width" "240px"
    , style "margin" "40px auto 0"
    ]
    [ h2 [ style "margin-bottom" "8px" ] [ text "Links" ]
    , ul
        [ style "list-style-position" "inside"
        , style "padding" "0"
        , style "margin" "0"
        ]
        (List.map viewLink links)
    ]
```

## 最終調整

このような形でブログのひな型が完成に近づいてきました。
- 記事の表示
-　Aboutの調整

ここからレイアウト改善、ページ構成のリファクタリング、Markdown記事対応をメインに書きます。

## 1. レイアウトの見直し

初期状態はブラウザのデフォルトスタイルのままで、以下の問題があった。

- 本文の幅が画面いっぱいに広がっていた
- リストのデフォルト装飾（青リンク・下線）がそのまま残っていた
- ヘッダーとナビが整理されていなかった

### 対応

- `Layout.elm` を新規作成し、共通ヘッダー・ナビ・CSSを一箇所に集約
- `Html.node "style"` でCSSを埋め込み、ビルド構成に依存せず反映されるようにした
- コンテナ幅を `max-width: 680px` 程度に絞り、余白を意識したレイアウトに変更
- 記事一覧をビュレットのリストから、タイトル＋日付を横並びにした行区切りのリストに変更

## 2. 記事データの一元管理

記事タイトルが `Home.elm` の一覧と `Post.elm` のh1見出しの両方に別々にハードコードされており、情報がズレる可能性があった。

### 対応

- `src/Data/Articles.elm` を新規作成
- `Article` 型（`id`, `title`, `date`）と `all : List Article`、`findTitle : Int -> String` を定義
- `Home.elm` は `List.map postItem Articles.all` で一覧を動的生成
- `Post.elm` は `Articles.findTitle id` でタイトルを取得する形に統一

## 3. ページ構成のリファクタリング（Model分割）

元々 `Main.elm` の `Model` は `route` フィールドだけを持ち、各ページの `GotXxxMsg` を握りつぶす実装になっていた。Markdown記事を `Http.get` で取得する際、この構造だと結果を受け取れないことが判明。

### 対応

- `Page` 型（`HomePage Home.Model | PostPage Post.Model | AboutPage About.Model | NotFoundPage`）を導入
- `Model` を `{ key : Nav.Key, page : Page }` に変更（`route` フィールドは削除）
- `initPage : Route -> Nav.Key -> ( Page, Cmd Msg )` でルート変更時に各ページの `init` を呼び、発行された `Cmd` を確実に返すように修正
- `update` で `GotPostMsg` を `Post.update` に委譲し、結果を `Model` に反映

### つまずいたポイント

- `Home.elm` / `About.elm` の `init` が旧シグネチャ（`() -> Url -> Nav.Key -> (...)`）のまま残っており、型不一致エラーが連発
  → 使っていない引数（`Url`, `Nav.Key`）を削除し、シンプルな `init : ( Model, Cmd Msg )` に統一
- `About.elm` で `LinkItem` 型を参照しているのに `type alias` 宣言がなく `NAMING ERROR`
  → `type alias LinkItem = { label : String, url : String }` を追加して解決

## 4. Markdown記事対応

記事本文をElmの `Html` 直書きにしていたが、限界を感じたため `elm-explorations/markdown` を導入。

- `Post.elm` に `Status = Loading | Loaded String | Failed` を持たせ、`Http.get` で `/articles/{id}.md` を取得
- 取得した文字列を `Markdown.toHtml [ class "article-body" ] raw` で描画
- `Layout.elm` のCSSに `.article-body` 用のスタイル（見出し・段落・リストの余白調整）を追加

### 静的ファイルの配置

開発サーバーが `npx elm-live src/Main.elm --open -- --output=main.js`（`--dir` オプションなし）だったため、`elm.json` と同じ階層（プロジェクトルート）がそのまま配信ルートになることが判明。

```
elm-web/
  articles/
    1.md
    2.md
    3.md
  src/
  elm.json
  index.html
  main.js
```


## AI活用についての考察

AIを使うかどうかに対してはどのような学習をしたいかによって必要かどうかなんとなくわかってくるような気がします。

Elmそのものの挙動を勉強したいならAIを使ったエラー解消はよくないのかもしれません。言語そのものを理解していないからクリティカルなエラーの対応が分からないというか。

仮定を出し尽くしたけど解決方法が全く分からなかった。単純実装のみを目的としているならこの実装そのものを改善するというよりかは今回のエラーの対応の回答方法を知ったほうがいいのかもしれない。

調べてもクリティカルな解決方法が出てこないときAIにきいてみたらがっつり解決の糸口を書いてくれます。

GitHubとかから書かれている本当の書籍方法を持ってくるのでしょうが、人間が調査するには膨大な中からboolしていくのがあまり良いとは言えない。

知らないことがあればその公式文章を持ってくればかなり挙動しかり、ルールを学習することが出来るのでしょうが。

その応用方法を試されているでしょうか。
